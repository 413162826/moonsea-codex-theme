### 有效做法

- X 的主题页 Open Graph 卡片能正确展示主题名、描述和入口；图片上传受浏览器文件选择器影响时，链接卡片比无图纯文本更稳定。
- 小红书必须点击“话题”并从平台建议列表选择。编辑器出现 `[话题]` 标记才说明写入的是话题对象；手打 `#文字` 不能作为标签生效证据。
- 小红书使用 3:4 竖版封面，正文先讲“为什么做”，再讲一键应用体验，最后用三选一提问承接评论，比跨平台复制产品公告更符合平台语境。
- 每个平台使用独立 UTM；无法携带可点击外链的平台只记录曝光和互动，不虚构下载归因。

### 失败原因与下一次假设

- X 配图文件选择器未稳定完成上传；本次改用已验证的主题页链接卡片。下一次优先检查卡片预览，不再为单张配图反复消耗发布窗口。
- 小红书提交后曾短暂显示“审核中”，复查后已进入“已发布”列表；裸 `explore/{noteId}` 在网页端仍会因缺少平台 `xsec_token` 返回 404，不能把裸地址当作可分享链接。
- 小红书编辑器中的三个标签均显示 `[话题]` 对象标记，证明平台已识别；下一次仍应在带平台分享令牌的公开页继续复核可点击状态。
- 昨日内容曝光低且几乎无互动。下一次继续测试“视觉反差强的原创角色 + 明确提问”，并比较其公开后 24 小时浏览、互动和独立 UTM 访问是否高于纯产品预告。
- 下载目标必须同时看下载事件、下载访客和重复下载；在访客数明显偏低时，不用累计事件数包装增长。

### 有效做法

- 宣传前先部署并截图线上版本，确保帖子中的“封面已通用”与用户当前可访问的 v22 一致。
- 小红书提交后先记为“审核中”，只有后台卡片不再显示审核标记、能够进入公开 `explore` 页面，并且三枚标签都呈现为可点击链接后才改记“已公开”。
- 小红书正文编辑器是结构化富文本。脚本插入正文时应一次性设置编辑器内容并触发输入事件；话题必须把光标移到正文末尾，再通过建议列表逐个选择。
- X 的翻译扩展弹窗会遮挡发布按钮；关闭弹窗后使用页面原生按钮提交，并以首页时间线和独立状态页双重验证。
- VibeCafé 适合写开发过程与取舍，不适合照搬 X 的短广告。作品地址应直接写入正文，发布后在详情页复核为可点击链接；只依赖编辑器的链接附件不能作为成功证据。

### 失败原因与下一次假设

- 小红书搜索索引在审核刚结束时有延迟，搜索不到不能直接判定失败；应回到“全部”列表检查状态，再进入公开页验证。
- VibeCafé 首次使用需要 GitHub OAuth，只申请只读邮箱和资料；发布后默认用户名仍是随机值。下一次发帖前可单独完善用户名和头像，但不把资料装修混入当天增长闭环。
- 三个平台均使用同一组真实截图，但文案分别采用体验叙述、功能短讯和开发复盘。明日复核应比较各平台 24 小时浏览、互动与官网来源，决定 WorkBuddy 后续优先渠道。
