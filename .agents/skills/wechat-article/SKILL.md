# 公众号图文发布

## 适用范围

负责从已核验的文章素材生成微信公众号图文稿，并在用户已授权的固定浏览器会话中完成上传、封面、预览、草稿或发表。它不负责申请认证、获取 AppSecret、绕过验证码或绕过平台审核。

公众号网页后台和官方 API 是两条能力边界。网页能够发表，不代表 API 权限已开通。没有实测 API 权限时，使用网页后台；不要把 API token、Cookie 或 AppSecret 写入仓库、日志或文章。

## 前置检查

1. 先使用 `cookie-skill` 的 `status` 和 `path`，确认 AI profile 是 `C:\Users\Administrator\.codex\skills\cookie-skill\data\profile`。
2. 使用固定的 `agent-browser` 会话 ID，并用 `--restore` 恢复；不要每次创建临时会话。
3. 确认当前公众号名称和登录身份。账号未认证不等于不能通过网页发表，但认证状态、群发额度和 API 权限必须单独记录。
4. 内容先交给 `$human-writing` 生成或改稿，再做事实、链接、图片版权和敏感内容检查。

## 素材合同

每篇文章至少需要：

- 标题、作者署名、摘要
- 正文 Markdown 或 HTML
- 正文插图，按正文出现顺序编号
- 一张封面候选图（优先使用正文首图）
- 原文链接（放在正文和“阅读原文”字段时分别确认）

正文图片必须先上传到公众号编辑器或素材库，不能依赖月海站点的外链直接作为正文图。上传后检查图片实际出现在编辑器 DOM 中，且没有空白占位。封面必须存在，否则发表会被“必须插入一张图片”拦截。封面应保证缩略图裁切后主体仍清楚，摘要独立填写，不依赖自动截取。

## 正文视觉排版标准

公众号正文不能只是一串普通段落和图片。每篇文章先设计阅读节奏，再粘贴到编辑器：

- 开头用一段短引子说明今天要看什么，控制在 2 至 4 行；不要把摘要原样重复一遍。
- 正文按主题拆成 3 至 5 个区块，每个区块有短标题或编号、1 至 3 段短文和一张对应图片；避免一张长文字墙。
- 图片前后都要有关系明确的文字，图片下方可加一行简短图注，说明主题名、适用氛围或关键设计点；不要只把图片孤零零地堆在文末。
- 使用编辑器原生标题、加粗、分隔线、引用/提示块和留白建立层级，保持同一篇文章的字号、颜色和间距一致。不要用大量圆圈、彩色 emoji 或连续感叹号代替排版。
- 壁纸推广优先采用“总览图 → 单张主题卡 → 应用方式 → 官网入口”的顺序；总览图只做一次，单张图按编号对应主题名，结尾只保留一个明确行动入口。
- 正文图片宽度、比例和清晰度要统一；移动端预览时检查图片是否被裁切、文字是否压在主体上、段落是否出现孤行。
- 排版完成后必须在公众号编辑器预览中检查首屏、图片顺序、标题层级、图注和链接，再保存草稿；只检查 DOM 中有图片不等于完成视觉验收。

## 发布流程

1. 打开公众号图文编辑入口，创建单图文稿；填写标题、作者和摘要。
2. 按“短引子—主题区块—应用方式—官网入口”组织正文，先完成标题层级、分隔线、图注和留白，再按顺序上传并插入图片；图片上传完后检查数量和顺序。
3. 在“封面和摘要”中从正文选择首图，检查封面预览和摘要。
4. 先保存草稿。草稿只代表内容已保存，不代表已公开。
5. 按用户授权选择“发表”或“群发”。“发表”用于生成可访问的文章记录；“群发”会向粉丝推送并消耗平台额度，不能默认替用户群发。
6. 预览链接中的 `tempkey` 只用于测试，不计为公开链接。发表后从发表记录取得永久文章 URL。
7. 使用无登录窗口或 `Invoke-WebRequest` 访问永久 URL，核对返回状态、标题、摘要和正文图片；只有验证通过才记录“已发布”。

## 失败处理

- 出现“必须插入一张图片”：回到封面设置，从正文选择已上传的首图，重新保存后再发表。
- 只有预览 URL、没有永久 URL：记录“已预览/未发表”，不要宣称已发布。
- 发表按钮被拦截或出现认证提示：保留草稿，记录页面原文；不要反复提交，也不要尝试绕过。
- API 返回未授权：回到网页流程；不要把网页登录 Cookie 当成 API 凭据。
